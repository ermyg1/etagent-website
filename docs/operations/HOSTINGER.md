# Hostinger Deployment

The E.T Agent Website is deployed to Hostinger as a static React application.
The production package is generated by Vite in `dist/`.

## Static React Deployment

The application is built locally or in a trusted build environment with:

```sh
npm run build
```

The generated `dist/` directory contains the complete static deployment package
for Hostinger.

## Why Only `dist/` Contents Are Uploaded

Hostinger serves the built static files. It does not need the source repository,
React source modules, TypeScript files, local dependencies, or development
configuration.

Only the contents of `dist/` should be uploaded because those files are the
browser-ready production output.

## Why `.htaccess` Is Required

The website is a single-page application. Direct visits to nested routes must be
rewritten to `index.html` so React can render the correct route in the browser.

The `.htaccess` file provides this rewrite behavior on Hostinger's Apache-based
static hosting.

## Why Cache Clearing Matters

Hostinger may continue serving cached files after upload. Clearing the Hostinger
cache ensures visitors receive the latest `index.html`, assets, and routing
rules.

## SPA Routing

In a single-page application, routes such as `/governance-model`,
`/governance-demo`, and `/trust` are handled by the client application after
`index.html` loads.

Without the `.htaccess` rewrite, refreshing or directly opening those routes can
produce a server-side 404 because the static host looks for a physical file or
folder at that path.

## Common Upload Mistakes

- Uploading the repository root instead of `dist/` contents.
- Uploading `src/`, `node_modules/`, or configuration files.
- Replacing `index.html` without uploading the matching `assets/` folder.
- Uploading new assets without deleting old assets first.
- Forgetting to upload `.htaccess`.
- Forgetting to clear Hostinger cache.
- Verifying only the homepage and missing direct-route refresh behavior.

## Correct Deployment Order

1. Run `npm run build`.
2. Open `dist/`.
3. Confirm `index.html`, `assets/`, and `.htaccess` exist.
4. Delete the old `assets/` folder from Hostinger.
5. Upload the new `assets/` folder.
6. Replace `index.html`.
7. Upload `.htaccess`.
8. Clear Hostinger cache.

## Verification Procedure

After deployment and cache clearing, verify:

- `/`
- `/governance-model`
- `/governance-demo`
- `/trust`

Each route must load directly, refresh successfully, and display the expected
production page on desktop and mobile viewport sizes.
